ALGORITHM THEORY

🔍 1. WHAT IS DEADLOCK?

Deadlock is a situation where a set of processes are blocked because each process is holding a resource and waiting for another resource held by some other process.

Real-world Analogy: A 4-way traffic jam where every car is blocked by the car in front, and no one can move.

⚠️ 2. THE FOUR CONDITIONS (COFFMAN CONDITIONS)

Deadlock can only occur if all four of these are true simultaneously:

  • Mutual Exclusion: Only one process can use a resource at a time.
  • Hold and Wait: A process holds one resource while waiting for another.
  • No Preemption: Resources cannot be forcibly taken from a process.
  • Circular Wait: A closed chain of processes exists where each waits for the next.

🏦 3. DEADLOCK AVOIDANCE (BANKER'S)

The Banker's Algorithm checks if granting a resource keeps the system in a Safe State by simulating future allocations.

Time Complexity: O(m * n²)
Key Formula: Need[i][j] = Max[i][j] - Allocation[i][j]
Safety Check: Request[i] <= Need[i] AND Request[i] <= Available

🕸️ 4. DEADLOCK DETECTION (RAG/DFS)

In single-instance systems, a cycle in the Resource Allocation Graph (RAG) indicates a deadlock.

Algorithm: Depth First Search (DFS)
Time Complexity: O(V + E)
Wait-for Graph: A condensed RAG showing only process dependencies.

🛠️ 5. RECOVERY STRATEGIES

Method Complexity Approach
Abort All O(k) Killing all deadlocked processes.
Victim Selection O(1) Killing the process with minimum priority.
Preemption O(m) Reclaiming resources with rollback support.
